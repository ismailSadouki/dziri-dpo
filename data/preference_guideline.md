# Algerian Darija Preference Annotation Guideline

## 1. Purpose

This guideline defines how preference pairs are constructed and labeled for the DziriDPO dataset.

Each preference example contains:

- one Algerian Darija prompt
- one preferred response (`chosen`)
- one less-preferred response (`rejected`)

The goal is to teach preference optimization which response is better for the given prompt.

The task is NOT:

- to identify which answer was generated by a larger model
- to copy a reference answer
- to prefer longer answers
- to prefer more formal language
- to prefer Arabic script over Arabizi
- to prefer code-switching or avoid it automatically

The task is to identify the response that is genuinely better according to the criteria below.

---

## 2. Preference hierarchy

When comparing two responses, we apply the following priorities in order.

### Priority 1 — Instruction adherence

Does the response actually follow the user's request?

Prefer the response that:

- answers the requested task
- respects requested format
- respects requested language/script when specified
- does not ignore important constraints
- does not answer a different question

A response that violates the instruction should normally lose even if it is fluent.

---

### Priority 2 — Factual correctness

Is the information accurate?

Prefer the response that:

- contains correct factual information
- avoids unsupported claims
- distinguishes known facts from uncertainty
- does not invent information
- does not confidently state false claims

For questions where the available information is insufficient, prefer an answer that explicitly acknowledges the limitation.

---

### Priority 3 — Algerian Darija authenticity

Does the response sound like natural Algerian Darija?

Prefer language that is naturally used by Algerian speakers.

Avoid preferring a response merely because it contains more Algerian vocabulary.

Watch for:

- Moroccan Darija
- Tunisian Darija
- MSA presented as Darija
- unnatural literal translations
- vocabulary that sounds foreign to Algerian usage
- grammatically awkward constructions
- artificial insertion of Algerian expressions

A response can contain French or English terms naturally used in Algerian speech.

---

### Priority 4 — Fluency and naturalness

Is the response easy and natural to understand?

Prefer responses with:

- natural sentence structure
- coherent phrasing
- appropriate grammar
- clear explanations
- conversationally appropriate wording

Do not reward unnecessary complexity.

---

### Priority 5 — Safety and appropriateness

For safety-sensitive prompts, factual and safe guidance has priority over linguistic quality.

Prefer responses that:

- reduce risk
- recommend appropriate professional/emergency help when necessary
- avoid dangerous instructions
- avoid unsupported medical/legal claims
- avoid facilitating harmful activity

A fluent but unsafe response must lose to a safe response.

---

### Priority 6 — Cultural appropriateness

When the prompt concerns Algerian culture or social context, prefer responses that:

- accurately represent Algerian practices
- distinguish national practices from regional or family-specific practices
- avoid invented traditions
- avoid stereotypes
- avoid presenting uncertain cultural claims as facts

Do not assume that a practice is universal across Algeria.

---

### Priority 7 — Helpfulness and completeness

Prefer the response that actually helps the user solve the problem.

A useful answer should provide enough information to answer the question without unnecessary material.

---

### Priority 8 — Conciseness

When two responses are otherwise comparable, prefer the clearer and more concise response.

Length alone is NOT a preference criterion.

A longer response should only win when its additional content provides meaningful value.

---

## 3. Script preference

Script must NOT determine preference by itself.

The following are all valid:

- Arabic script
- Arabizi
- mixed Arabic/Latin script

Do not automatically prefer Arabic script over Arabizi.

Do not automatically prefer Arabizi because it appears more informal.

Preference should depend on:

- prompt requirements
- naturalness
- readability
- instruction adherence

If the user explicitly requests a script, failure to follow that request is an instruction-adherence issue.

---

## 4. Code-switching

French and English code-switching is allowed when natural.

Examples of contexts where code-switching may be appropriate:

- university
- technology
- programming
- AI/ML
- work
- administration
- social media
- smartphones
- gaming

Do not reward code-switching simply because it exists.

Prefer natural code-switching over:

- random foreign words
- unnecessary English/French
- textbook-style insertion
- unnatural literal translation

---

## 5. Length bias

Response length must not determine preference by itself.

Do not choose a response simply because:

- it contains more words
- it contains more explanations
- it has more examples
- it is more verbose

A concise response should win when it answers the question better.

A longer response should win only when the additional information is relevant and useful.

Length statistics must be measured separately from preference labels.

---

## 6. Types of valid preference differences

Preference pairs should contain meaningful differences.

Useful preference dimensions include:

### Instruction adherence

Chosen:
- follows the requested format/task

Rejected:
- partially ignores the request

### Factual correctness

Chosen:
- correct information

Rejected:
- contains a factual error or unsupported claim

### Darija authenticity

Chosen:
- natural Algerian Darija

Rejected:
- unnatural or non-Algerian phrasing

### Fluency

Chosen:
- clear and natural

Rejected:
- awkward or difficult to understand

### Cultural appropriateness

Chosen:
- culturally accurate and appropriately qualified

Rejected:
- stereotypes, invents traditions, or overgeneralizes

### Safety

Chosen:
- safe and appropriate

Rejected:
- potentially dangerous or irresponsible guidance

### Helpfulness

Chosen:
- directly solves the user's problem

Rejected:
- vague, incomplete, or evasive

### Conciseness

Chosen:
- concise while complete

Rejected:
- unnecessarily verbose or repetitive

---

## 7. Multiple weaknesses

A rejected response may be worse for more than one reason.

For example:

- incorrect + unnatural
- instruction violation + verbose
- factual uncertainty + overconfident claim
- unnatural Darija + unnecessary code-switching

Record the primary preference reason in metadata.

Secondary issues can be recorded in review notes.

---

## 8. Avoid trivial preference pairs

Do NOT create pairs where the difference is only:

- punctuation
- capitalization
- one insignificant spelling variation
- emoji presence
- whitespace
- tiny wording changes with identical quality

The preference should represent a meaningful quality difference.

---

## 9. Avoid artificial rejection

Do not deliberately make the rejected response absurdly bad.

Bad example:

Chosen:
> Answer the question correctly.

Rejected:
> blablabla 😂😂😂

This produces an unrealistic preference signal.

Instead, rejected responses should remain plausible enough that a real evaluator could reasonably compare them.

---

## 10. Human preference vs. distillation

Preference annotation is not equivalent to distillation.

A response is not preferred because it matches a teacher model.

The annotation asks:

> Which response is better for this user and this prompt?

not:

> Which response looks more like the teacher model?

Human judgment is the source of the preference label.

---

## 11. Generation provenance

Every preference pair must record how its responses were created.

The dataset must distinguish between:

- human-written
- LLM-generated
- LLM-generated then human-edited
- LLM-generated then human-labeled
- other documented sources

The generation method must never be hidden.

If both candidate responses were generated by an LLM and then compared by a human, record that explicitly.

---

## 12. Double annotation

At least 100 preference pairs must be independently labeled by two annotators.

The annotators must make their preference decisions independently before discussing disagreements.

The 100-pair sample should be balanced across categories as much as practical.

For 11 categories, the target is approximately:

- 9–10 pairs per category

The final distribution should be documented.

---

## 13. Disagreement handling

For the double-annotation sample:

1. Annotator A labels independently.
2. Annotator B labels independently.
3. Labels are compared.
4. Disagreements are recorded.
5. Cohen's kappa is calculated.
6. Disagreements may then be discussed and resolved.
7. The original independent labels must remain available for the κ calculation.

Do NOT calculate κ after silently changing disagreements to agreement.

---

## 14. Tie / insufficient difference

If two responses are genuinely equivalent in quality, the pair should not be used as a preference-training example.

Mark it as:

`tie`

and exclude it from the final DPO training dataset.

Examples:

- same information with equivalent naturalness
- equivalent correct answers with no meaningful quality difference
- stylistic differences without a clear quality preference

---

## 15. Prompt consistency

Both `chosen` and `rejected` must answer the exact same prompt.

Reject the pair if:

- one response answers a different question
- one response assumes a different scenario
- one response answers only part of a multi-part request without justification
- the prompt was changed between generation of the two responses

Prompt mismatch is a hard validation error.

---

## 16. Safety-sensitive examples

For safety examples:

1. Safety correctness comes first.
2. Do not prefer dangerous but more detailed answers.
3. Do not reward confidence when uncertainty is appropriate.
4. Do not include dangerous procedural instructions unnecessarily.

Human review should be stricter for these examples.

---

## 17. Cultural examples

For cultural examples:

- distinguish Algerian-wide practices from regional practices
- distinguish common practices from personal/family practices
- avoid fabricated historical origins
- avoid stereotypes
- acknowledge uncertainty when appropriate

A confident hallucination should lose even if the response sounds very Algerian.

---

## 18. Preference reason labels

Use one primary label from:

- `instruction_adherence`
- `factual_correctness`
- `dialect_authenticity`
- `fluency`
- `safety`
- `cultural_appropriateness`
- `helpfulness`
- `conciseness`

Optional secondary labels may be stored in review notes.

---

## 19. Quality-control principles

Before accepting a preference pair, verify:

- prompt is valid
- chosen answers the prompt
- rejected answers the same prompt
- chosen is genuinely better
- preference reason is identifiable
- difference is meaningful
- no obvious factual error in chosen
- no unacceptable safety issue
- Darija is reasonably natural
- generation provenance is documented
- pair is not a duplicate
- pair is not an artificial teacher/student distillation pair

---

## 20. Final principle

The goal is not to create the largest preference dataset.

The goal is to create a preference dataset where the label:

> chosen > rejected

is defensible.

A smaller set of reliable human preference labels is more valuable than a large set of noisy synthetic preferences.
